## 1. Project Overview

### 1.1 Project Name
HouseRentLk

### 1.2 Purpose
HouseRentLk is a user-friendly web platform designed to connect house owners, renters, and verified brokers in Sri Lanka's rental market. It enables owners to list properties efficiently, renters to discover suitable homes via advanced search, and brokers to manage listings professionally. The focus is on transparency, security, and localization to address common pain points like unverified ads, location mismatches, and fraud in the local industry.

### 1.3 Scope
- **Core Features:** User registration by role, property listing management, advanced search/filtering, secure contacting, favorites, and messaging.
- **Sri Lanka-Specific Adaptations:** Integration with local maps (e.g., Google Maps with Sri Lankan postal codes), currency in LKR, compliance with Rent Act (e.g., mandatory disclosure of lease terms), and amenities tailored to local needs (e.g., servant quarters, well water, or temple proximity).
- **Exclusions:** No sales, short-term rentals (e.g., Airbnb-style), or non-house properties. Future expansions could include annexes or boarding houses.
- **User Scale:** Designed for 10,000+ active users, with scalability for peak seasons (e.g., post-New Year migrations).
- **AI Enhancements:** Built-in hooks for future AI (e.g., price prediction based on Central Bank data or neighborhood safety scores).

### 1.4 Technology Stack
| Layer | Technology | Rationale |
|-------|------------|-----------|
| **Frontend** | React.js (with Hooks, Redux for state management) | Modern, component-based UI for responsive design; supports PWAs for mobile users in rural Sri Lanka with intermittent internet. |
| **Backend** | Node.js + Express.js | Efficient API handling; scales well for real-time features like messaging. |
| **Database** | MongoDB (with Mongoose ODM) | Flexible schema for varying property details; geospatial queries for location-based search. |
| **Authentication** | JWT + bcrypt for passwords; Optional OAuth (Google/Facebook) | Secure and stateless; compliant with Sri Lanka's data protection laws. |
| **Hosting/Deployment** | Vercel (for frontend) + Heroku/AWS EC2 (for backend) + MongoDB Atlas | Cost-effective for startups; AWS for local data residency if needed. |
| **Additional** | Cloudinary for image storage/optimization; Socket.io for real-time messaging; Optional AI: TensorFlow.js or Python (Flask) microservices integrated via API. |

### 1.5 Assumptions and Dependencies
- Users have basic internet access (e.g., via Dialog or SLT in Sri Lanka).
- Integration with external APIs: Google Maps API for geolocation, EmailJS/SendGrid for notifications.
- Dependencies: Node v18+, React v18+, MongoDB v6+.

## 3. User Types & Permissions
Roles are assigned during registration, with admin approval for brokers to ensure verification (e.g., upload NIC or business registration).

### 3.1 Admin
- Full access: View/edit/delete all listings, users, messages, and reports.
- Analytics: User growth, listing trends by province (e.g., high demand in Colombo vs. Kandy).
- Moderation: Approve/reject listings, handle disputes per Rent Act guidelines.
- Settings: Manage locations (provinces: Western, Central, etc.), categories (e.g., furnished/unfurnished), and AI toggles.

### 3.2 Owner
- Manage own listings: Create, edit, deactivate (e.g., when rented out).
- View inquiries: Messages and contact stats.
- Profile: Upload verification docs (e.g., deed excerpts) for trust badges.

### 3.3 Renter
- Browse/search: Full access to public listings.
- Interact: Save favorites, contact via form (hides personal details).
- Profile: Preferences (e.g., preferred districts like Negombo for beach proximity).

### 3.4 Broker
- Similar to Owner, but with multi-owner support (e.g., tag listings as "managed by broker").
- Verification required: Upload license; admins review within 24 hours.
- Advanced tools: Bulk uploads, client management.

### 3.5 Guest (Unregistered)
- Limited browsing: View listings without contacts or saves.
- Prompted to register for full features.

## 4. System Architecture
High-level diagram (text-based):
```
Client (React App) <-- HTTPS/REST APIs --> Backend Server (Node/Express)
  |                                        |
  +-- Browser Storage (JWT)                +-- MongoDB (Data Storage)
                                             |
                                             +-- External Services: Cloudinary (Images), Google Maps (Geolocation), AI Microservice (Predictions)
                                             +-- Real-Time: Socket.io for Notifications/Messaging
```
- **Microservices Approach:** AI features as separate Node/Python service for scalability.
- **Data Flow:** Users interact via frontend; backend validates and stores in DB.

## 5. Functional Requirements

### 5.1 Authentication & User Management
- Register: Email/phone + password; role selection; CAPTCHA for spam prevention.
- Login/Logout: Session persistence via JWT (7-day expiry).
- Password Reset: Email link with OTP.
- Social Login: Google/Facebook (optional, for quick sign-up in Sri Lanka's mobile-first market).
- Profile: Edit details, upload photo/NIC for verification badges.
- Role Upgrade: Renters can apply to become brokers with doc upload.

### 5.2 Property Listings
- Create/Edit/Delete: Multi-step form with real-time validation.
- Fields: Title, Description (up to 1000 chars), Price (LKR/month), Bedrooms (1-10), Bathrooms, Size (sq.ft/perch), Amenities (checkboxes: AC, Parking, Garden, Well, Servant Quarters, Temple/School Proximity).
- Location: Province/District/City dropdowns (e.g., Western > Gampaha > Negombo); Optional lat/lng via map picker.
- Media: Upload 5-15 images/videos (max 10MB each); Auto-compression.
- Status: Draft, Pending Approval, Active, Rented (auto-expire after 6 months).
- Sri Lanka-Specific: Mandatory fields for lease type (e.g., 1-year min per Rent Act), advance payment details.

### 5.3 Search & Filtering
- Keyword Search: Full-text on title/description/location.
- Filters: Price slider (LKR 10k-500k), Bedrooms/Bathrooms, Amenities, Furnished Status, Proximity (e.g., <5km from beach in Negombo).
- Advanced: Sort by Relevance/Newest/Price; Pagination (20 results/page).
- Map View: Interactive Google Maps with pins, clustering for dense areas like Colombo.

### 5.4 Listing Details Page
- Gallery: Slider with zoom/lightbox.
- Details: All specs + owner/broker profile (verified badge).
- Map: Embedded view with directions.
- Contact: Form sending message (no direct email/phone reveal to prevent spam).
- Related Listings: AI-suggested similar properties in same district.

### 5.5 User Interactions
- Favorites: Save/remove listings; View in dashboard.
- Messaging: In-app inbox; Real-time notifications via email/SMS (integrate Twilio for Sri Lanka numbers).
- Reports: Flag suspicious listings (e.g., fraud) for admin review.

### 5.6 Admin Tools
- Dashboard: Charts (e.g., listings per province using Chart.js).
- Bulk Actions: Approve multiple listings.
- Analytics: Integration with Google Analytics; Export CSV reports.

## 7. Non-Functional Requirements

### 7.1 Performance
- Page Load: <2s (optimize with lazy loading, code splitting).
- API Latency: <200ms; Use caching (Redis) for frequent queries.
- Scalability: Handle 1k concurrent users; Auto-scale on AWS.

### 7.2 Security
- HTTPS everywhere; Input sanitization (xss protection).
- Data Privacy: Compliant with Sri Lanka's Personal Data Protection Act (store data locally if possible).
- Fraud Prevention: Rate limiting, AI flagging unusual activity (e.g., multiple listings from one IP).
- Encryption: Passwords hashed; Messages encrypted at rest.

### 7.3 Usability & Accessibility
- Mobile-First: 70% of Sri Lankan users on mobile; Test on low-end devices.
- Localization: English/Sinhala/Tamil support (using i18n).
- Accessibility: ARIA labels, keyboard navigation.

### 7.4 Reliability
- Uptime: 99.9%; Error logging with Sentry.
- Backup: Daily DB snapshots.

## 8. Database Schema (Detailed MongoDB Models)
```javascript
// Users Collection
{
  _id: ObjectId,
  name: String,
  email: String (unique),
  phone: String (optional, validated for SL format),
  passwordHash: String,
  role: Enum['admin', 'owner', 'renter', 'broker'],
  profilePic: String (URL),
  verified: Boolean (for brokers),
  preferences: { districts: [String], priceMax: Number }, // For renters
  createdAt: Date
}

// Listings Collection (with Geospatial Index on location)
{
  _id: ObjectId,
  ownerId: ObjectId (ref Users),
  brokerId: ObjectId (optional, ref Users),
  title: String,
  description: String,
  images: [String] (URLs),
  price: Number (LKR),
  beds: Number,
  baths: Number,
  size: Number (sq.ft),
  amenities: [String] (e.g., ['AC', 'Garden', 'Servant Quarters']),
  location: {
    province: String (e.g., 'Western'),
    district: String (e.g., 'Gampaha'),
    city: String (e.g., 'Negombo'),
    geo: { type: 'Point', coordinates: [Number, Number] } // [lng, lat]
  },
  leaseType: Enum['Monthly', 'Yearly'],
  advanceMonths: Number,
  status: Enum['draft', 'pending', 'active', 'rented', 'rejected'],
  views: Number,
  createdAt: Date
}

// Messages Collection
{
  _id: ObjectId,
  fromUser: ObjectId,
  toUser: ObjectId,
  listingId: ObjectId,
  message: String,
  read: Boolean,
  createdAt: Date
}

// Reports Collection
{
  _id: ObjectId,
  reporterId: ObjectId,
  targetId: ObjectId (listing or user),
  reason: String,
  status: Enum['open', 'resolved'],
  createdAt: Date
}
```
